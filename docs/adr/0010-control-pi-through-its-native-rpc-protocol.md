# Control Pi through its native RPC protocol

Più will launch one bundled Pi process in RPC mode for each active chat and communicate with every chat child through Pi's native JSONL standard-input and standard-output protocol. A narrow host module owns process supervision, request correlation, event translation, steering, model and reasoning changes, abort, session restoration, and shutdown. A small bundled launcher constructs the child with Pi's public session APIs and hands it to Pi's official `runRpcMode` runner so Più can inject its Keychain-backed credential store without copying Pi's CLI bootstrap. Pi's session journal remains the conversation source of truth.

Pi's native RPC command set does not expose login or logout. Graphical authentication therefore runs in a separate short-lived helper that calls Pi's public `ModelRuntime.login()` API and translates only Pi's public authentication prompts and notifications for the native host. It never carries credential values; the same Keychain-backed credential store persists them directly. This helper is credential bootstrap, not a chat harness or agent transport. Chat processes remain unmodified native-RPC sessions.

This preserves Pi's project and application-owned resource discovery, `openai-codex` subscription authentication, current model metadata, and native semantics without adding an experimental HarnessAgent, sandbox, VFS mirror, or second agent lifecycle abstraction. AI Elements remains a frontend presentation dependency and does not participate in the agent transport.
