# Own the desktop interface system

Più will own its React product components and checked-in UI primitives while composing them from shadcn's Base UI Mira source, Tailwind CSS 4 semantic tokens, Lucide icons, and locally bundled Geist Sans and Geist Mono variable fonts. System light and dark appearance is the only theme input. T3 Code at commit `f035a0f4cdf4abaa6704673af7b5a4a321149ba2` is a licensed reference for desktop density, pane hierarchy, and composer behavior, not a frontend dependency or fork.

An owned-source composition keeps Più's project inbox, chat-draft persistence, Tauri boundary, and later Pi transport independent of another product's Electron, routing, state, provider, settings, and cloud architecture. Checked-in primitives make the accessible Base UI behavior auditable and let product components stay in Più's vocabulary. The interface uses one token map across every surface, with a 52-pixel traffic-light-safe titlebar, a transient 256-pixel sidebar default, compact controls, flush panes, quiet focus, reduced-motion fallbacks, and no configurable theme, font, or sidebar-width setting.

The initial projectless state has one central repository action. With projects and no active chat, All Projects deliberately targets the first available remembered project; a selected project takes precedence. This preserves exactly one retained draft per project while keeping the global inbox useful without adding a project selector to the composer. The same composer exposes centered and docked layouts so chat creation can reuse it without introducing a second input surface.

Substantial upstream source retains its license notice in `THIRD_PARTY_NOTICES.md`. Più adapts T3 Code's interaction principles and verifies its own implementation; it does not imply endorsement or copy T3's runtime boundaries.

The #3 opening route was approximately 225.8 KiB of raw JavaScript before the accessible Base UI behaviors and shared primitives were introduced. The first production build of this system measured 439,950 bytes raw and 140.06 kB gzip for JavaScript, plus 51,295 bytes raw and 10.03 kB gzip for CSS. That deliberate delta replaces provisional product controls with the approved shared system while all five feature-heavy future surfaces remain dynamic. The build therefore enforces evidence-based ceilings of 512 KiB raw / 160 KiB gzip JavaScript and 64 KiB raw / 16 KiB gzip CSS. Changing those ceilings requires recorded bundle analysis and continued opening-route deferral.
